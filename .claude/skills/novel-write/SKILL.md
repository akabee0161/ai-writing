# novel-write

## Overview

`projects/<name>/` に用意された章の指定内容（chapter file）・キャラクター設定・全体プロットを読み込み、章の草案（地の文＋会話文）を生成して `output/<実行日時>/chapter_<n>.txt` に保存する。プロジェクトの雛形自体を作る場合は novel-init スキルを使う（このスキルは既存プロジェクトの章生成が対象）。

モードは 2 つ。

| モード | 条件 | 動作 |
|--------|------|------|
| 全章モード | `--file` なし | `chapters/` 配下の全章ファイルを章番号順に、サブエージェントで 1 章ずつ**順次**生成する |
| 単章モード | `--file` あり | 指定した 1 章だけを、このセッション内で直接生成する |

## Argument Parsing

呼び出しは `--project <name> [--file <chapter-file>] [--chapter <n>]` の形式（順不同）。

- `--project` は必須。欠けている場合は対話的にユーザーへ質問して補完する。値を推測して埋めない。
- `--project` は `projects/` 配下の実在するディレクトリ名であること。存在しなければユーザーに確認する。
- `--file` を省略すると全章モードになる。
- `--chapter` は単章モードでのみ有効。省略された場合は章ファイルの Front Matter の `chapter` 値を使う。`--chapter` が指定された場合はそちらが Front Matter より優先される。**両方とも値が無い場合のみ**、ユーザーに章番号を質問する。全章モードで `--chapter` が指定されたら、無視せずユーザーに意図を確認する。

## パス

| 対象 | パス |
|------|------|
| 全体プロット | `projects/<project>/plot.md`（無ければスキップ） |
| キャラクター設定 | `projects/<project>/characters.yaml`（無ければスキップ） |
| 章ファイル | `projects/<project>/chapters/<file>` |
| 出力先 | `projects/<project>/output/<run-id>/chapter_<chapter>.txt` |

`<run-id>` は実行開始時に 1 回だけ `date +%Y%m%d-%H%M%S` で決める（例: `20260927-201500`）。1 回の実行で生成した章はすべて同じ `<run-id>` フォルダに入る。既存のフォルダ・ファイルは決して上書きしない（`output/` は Git 管理対象外で履歴から復元できないため）。同名フォルダが既にあれば `<run-id>` を取り直す。

## 単章モードの手順

1. **章ファイルを読む**
   先頭の YAML Front Matter（`---` で囲まれた部分）をメタデータとして解析する。
   - `chapter`: 章番号。`--chapter` 引数が与えられていればそちらを優先する
   - `characters`: この章に登場するキャラクター名のリスト
   Front Matter 以降の本文が、その章で描く場面・出来事・情景・感情の指定内容。
2. **キャラクター設定を読む**（`characters.yaml` が存在する場合）
   章ファイルの `characters` リストに列挙された名前と**完全一致**するキーのみを抽出する。一致しない名前があれば、キーの表記揺れ（全角/半角スペース、敬称など）を疑ってユーザーに確認する。抽出した各キャラクターの属性（年齢・性格・口調・外見など、キーは自由）をそのまま執筆時の設定として使う。
3. **全体プロットを読む**（`plot.md` が存在する場合）
   あらすじ・テーマ・章構成を、その章が全体の中でどう位置づくかの背景情報として使う。
4. **草案を執筆する** — 下記「執筆ルール」に従う。
5. **出力する** — `output/<run-id>/` を作成し、`chapter_<chapter>.txt` に本文のみ（YAML Front Matter なし。タイトル行は含む）を書き込む。保存先パスをユーザーに報告する。

## 全章モードの手順

1. **章ファイルを列挙・検証する**（執筆前にすべて確認し、問題があれば 1 章も書かずにユーザーへ確認する）
   - `chapters/*.md` をすべて読み、各 Front Matter の `chapter` を取得する。`chapter` が無いファイル、章番号の重複があれば確認する
   - 各章の `characters` が `characters.yaml` のキーと完全一致するか確認する（単章モード手順 2 と同じ基準）
   - 章番号を数値として昇順に並べる（`chapter10` が `chapter2` より前に来ないように）
2. **実行内容を確認する** — 生成する章の一覧（章番号・ファイル名）と出力先 `output/<run-id>/` をユーザーに示し、開始してよいか確認する。章数が多いと時間とコストがかかるため。
3. **1 章ずつ順次サブエージェントに書かせる**
   Agent ツール（`subagent_type: general-purpose`）を章番号順に 1 つずつ起動し、前の章の完了を待ってから次を起動する。**並列に起動しない**（将来、章をまたぐ設定メモを順に引き継ぐ前提の設計。GitHub Issue #1）。各サブエージェントへのプロンプトには以下を含める。
   - 読むファイルのパス: `plot.md`・`characters.yaml`（存在するもののみ）と、その章の章ファイル
   - 執筆ルール: 「`.claude/skills/novel-write/SKILL.md` の『執筆ルール』節を読み、それに従って書く」
   - `characters.yaml` からは章ファイルの `characters` に列挙された名前のキーのみを使うこと
   - 書き込み先の絶対パス（`output/<run-id>/chapter_<n>.txt`）。本文のみ、タイトル行を含む
   - 返答は「保存したパス・章タイトル・文字数」のみとし、**本文を返さない**こと（メインのコンテキストを膨らませないため）
4. **失敗時** — サブエージェントが失敗した、またはファイルが作成されていなければ、そこで停止する。完了した章と未完了の章をユーザーに報告し、残りは単章モード（`--file`）で生成できることを伝える。
5. **完了報告** — 出力フォルダのパスと、各章のタイトル・文字数の一覧を報告する。

## 執筆ルール

- 日本語の小説形式（地の文＋会話文）で書く。ハードコードされたテンプレート文は使わない
- 各キャラクターの口調・性格設定を厳密に守る。特に口調（語尾・方言・敬語レベル）は指定通りに再現する
- 章ファイル本文で指定された場面・出来事・演出上の指示（箇条書きの指示を含む）を必ず反映する
- `plot.md` があれば、その章が担う役割（伏線・展開の位置づけ）と矛盾しない内容にする
- 分量の指定が章ファイルに無ければ、1章として自然な長さ（目安2000〜4000文字、日本語の文字数でカウント）で書く。ただし場面が短く済む指示ならそれより短くてよい — 文字数を埋めるための水増しはしない
- `characters` リストに含まれるが、場面上ずっと台詞を持たない/退場が早いキャラクターについては、口調設定を無理に台詞で実演する必要はない。仕草・行動・地の文での描写（例: 話し方の癖が滲む一言だけ入れる、去り際の動作で性格を示す）で存在感を示せば足りる
- 出力冒頭に章タイトル行（例: `第一章　○○`）を含める。タイトルは章ファイル本文の指示から推測するか、無ければ内容に即して簡潔に付ける

## Common Mistakes

| 症状 | 原因 |
|------|------|
| キャラクターの口調が違う/反映されない | `characters.yaml` のキーと章ファイルの `characters` リストが不一致。表記揺れをまず疑う |
| 話の筋が全体プロットと矛盾する | `plot.md` を読まずに章ファイルの指示だけで書いている |
| 全章モードでメインのコンテキストが膨らむ | サブエージェントに本文を返させている、またはメインで本文を読んでいる。返答はパス・タイトル・文字数のみ |
| 章の順序がおかしい | ファイル名の文字列順で並べている。Front Matter の `chapter` を数値として並べる |
| 既存の草案が消えた | `<run-id>` フォルダを使わずに書き込んだ。毎回新しい `<run-id>` を使う |
| 引数が一部欠けている | 推測で埋めず、対話的に質問して補完する（`--file` 省略は全章モード、`--chapter` は Front Matter で代用可なので対象外） |
